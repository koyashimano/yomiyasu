# 言い直しテスト

SKILL.md 2章 Step 2 の言い直しテストの細部。1章の型に当たった箇所を修正するか残すかに迷ったとき、否定対比を修正するとき、残した箇所の書き方に迷ったときに読む。

## 1. 手順

型に当たった箇所ごとに、次の順で決める。

1. 修正した文の案を1つ書く。
2. 原文と案で、2章の6点が同じかを比べる。SKILL.md「最優先ルール: 意味の保持」の文の働き（事実、意見、依頼など）が同じかも見る。
3. 1つでも変わるなら、案を捨てて原文を残す。案を作り直して通るまで試すことはしない。
4. 全て同じなら案を採る。

文や語句を削る案は、6点を文ごとに比べず、削る部分にしかない主張、条件、数値、期限がないかで比べる。あれば削らずに残すか、同じ意味で本文へ移す。本文に残ったAIへの指示、言い直しの締め、定型の結びは、読者に向けた中身がなければ削ってよい（slop-catalog.md 6章）。

## 2. 6点の見方

| 点 | 同じといえるとき | 変わる案の例（合成。案を捨てる） |
|---|---|---|
| 何について述べるか | 主題と論点が同じで、別の概念にすり替えていない | この設計の要は単純さにある → この設計のねらいは単純さだ |
| 何を認め、何を否定するか | 認めたことと否定したことが入れ替わらず、否定が消えも増えもしない（否定対比のAを消す案のみ3章で決める） | 新しい手順で手戻りがなくなったわけではない → 新しい手順で手戻りがなくなった |
| 誰が誰にするか | 動作主と相手、頼むのか説明するのかの向きが同じ | 田中さんが山本さんに確認を頼んだ → 田中さんが確認した |
| 範囲と条件 | 「一部」「〜の場合だけ」「〜まで」などの限定と、それが掛かる動作が同じ | 管理者の場合だけ削除できる → 削除できる |
| 断定・推量・伝聞の強さ | 言い切り、推量、伝聞、可能の強さが同じ | 原因は設定の誤りとみられる → 原因は設定の誤りだ |
| 数値・固有名詞・時期 | 数、単位、名前、日付、「先月から」のような時期が同じ | 約30件の問い合わせ → 30件の問い合わせ |

- 語を言い換えたのみで6点が同じなら、案を採る（その日の午後を溶かした → その日の午後をまるごと使ってしまった）。
- 漢語や名詞化に置き換えた案は、6点が同じでも硬くなりやすい（字数が減っても硬くなる）。原文の和語の表現を言い換える案では、漢語や名詞化の表現を追加しない（slop-catalog.md 7章の名詞化の言い回し。直訳語をその分野で定着した呼び名に置き換えるのは、calques.md 4章のとおりこれに当たらない）。

  反対に、原文が文書で普通に使う漢語（確認する、使用する、停止する）なら、他の規則で修正する所でなければ、和語にする案は採らない（SKILL.md「直訳語、漢語の詰まり、連用形名詞」）。和語の動詞にすると、目的語を書かなければ何をしたかが決まらないときや、意味の幅が広がるとき（確認する → 見る）は、名詞の形や元の語を残す。

## 3. 否定対比（AではなくB）

否定対比は、他の型より主張が逆になりやすい。Aを消す案は、2章の「何を認め、何を否定するか」の代わりに次で確認する（他の5点は2章のとおり）。

1. Aを消してBのみを言う文を作り、原文と主張が同じかを見る。
2. 変わるなら残す。このときのAの否定は、読み手の思い込みや、検証で外れた仮説を正している。原文のままにし、読み違いや読みにくさを特定できたときのみ、否定を残して表現を整える（整え方は gemini-syntax.md 原則5）。否定と肯定を2文に分けた形（「Aではない。Bだ。」）は、Aを残して「AではなくBだ」の1文にまとめる。Aを消さないので、主張は変わらない。
3. 変わらないなら、Bのみを言う文にする。
4. 修正した後、消したAが肯定の文に移っていないかを確認する。「AとBのために」「Aに加えてB」「まずAを」のように、否定していた語が目的や優先の側に出ていたら、修正の仕方の誤り。

   check の diff は、否定していた語が「目的」「優先」「まず」などの語と同じ文に出たとき（見出しと「Aは使わず」「Aはせず」の文では、A を肯定した節に出たとき）と、「AとB」「Aに加えてB」「AだけでなくB」のように B と並べて肯定されたときに、意味が変わる恐れとして候補を出す。「まず、Aを減らす」「まず、Aを自動化する」のように A を減らす・変える推敲でも候補が出ることがあるので、候補が出たら、A が目的や優先の側に移ったのかを読んで決める。

   「Aを B に置き換える」「Aは B に置き換える」の形では出さないが、読点を挟んだ「Aを、B に置き換える」と「Aを B に変える」では出ることがある。見出しと「Aは使わず」「Aはせず」の文で、「まず」「第一に」などの語のみの句の後に、原文で肯定していた側の語を A より後ろに肯定で出した形（## 手作業ではなく自動化で回す → ## まず、手作業の手順を自動化する）も出さない。

   「Aのため」のみの形、否定していたのが動詞のとき、「お知らせ」のように平仮名で始まる語は拾えないので、候補がなくても読み比べる。

5. 変わるかどうか決められなければ残す。

技術検証の記事には「仮説ではX、実際はY」の対比が多い。否定対比を一律に修正すると、こうした記事が悪くなる。

### 残す例（合成）

| 原文 | 残す理由 |
|---|---|
| 遅かったのはデータベースではなく社内のネットワークでした。 | 読み手が疑いやすい原因を正している |
| 最初はメモリ不足を疑ったが、実際はファイルを開ける数の上限に達していた。 | 検証で外れた仮説と、実際の原因を並べている |
| 責めるつもりはなく、経緯を知りたいだけです。 | 相手の受け取り方を先に正している |
| この表の数字は売上ではなく受注の件数です。 | 読み違えやすい数の意味を正している |
| 新しいバージョンで速くなったのではなく待ち時間の表示を変えただけです。 | 誤解されやすい効果を打ち消している |
| 失敗ではなく条件を一つ確かめた結果でもある。 | 「でもある」の文。一文のまま残す（gemini-syntax.md 原則5） |
| この遅れは回線のせいではない。ほかの部署でも同じ時間に遅れていた。 | 後ろの文は否定の根拠を補っている（「では何か」を述べていない）。1文にまとめない |

### 直す例（合成）

| 原文 | 直した文 | 理由 |
|---|---|---|
| 必要なのは魔法ではなく、毎朝の確認の手順です。 | 必要なのは毎朝の確認の手順です。 | 魔法が必要だと考える読み手はいない。消しても主張が変わらない |
| このツールが集めるのは感想ではなく、操作のログです。 | このツールは操作のログを集めます。 | 前後に感想を集めると思わせる文がないときのみ。あれば残す |
| 必要だったのは新しい道具ではない。使い方をそろえることだった。 | 必要だったのは新しい道具ではなく使い方をそろえることだった。 | 2文に分けた否定対比。Aは残して1文にまとめ、「なく」の後に読点を追加しない（エッセイでも。小説の語りと会話、紹介記事・宣伝文で短い文を重ねた箇所は除く） |
| （前の文でロードバランサーの上限の話をしている）上限を超えたため503を返しました。 | 上限を超えたため、ロードバランサーが503を返しました。 | 前後から確定した主語を補う。6点は変わらない |

### 直し方を誤った例（合成）

| 原文 | 誤った直し | 正しい扱い |
|---|---|---|
| 見た目ではなく読み込みの速さを優先した。 | 見た目と読み込みの速さを優先した。 | 否定していた「見た目」が優先する側に移り、主張が逆になった。原文を残す。diff はこの形を「否定対比の主張が逆になった恐れ」として出す |

## 4. 報告の書き方

- 修正した箇所は「変えたところ」に、元の表現、書き直し後の表現、理由を書く。
- 残した箇所は「残したAIっぽいところ」に、表現と、変わってしまう点を1行で書く。例: 「最初はメモリ不足を疑ったが、実際は〜」を残した（否定対比。Aを消すと、外れた仮説が読めなくなる）。
- 案を捨てて残した箇所を「変えたところ」に書かない。修正していない箇所を、修正したと書かない。
