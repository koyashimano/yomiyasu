# 使い方の詳細

README の[使い方](../README.md#使い方)の節を詳しく書いたものです。

## 「/yomiyasu」とだけ送ったとき

「/yomiyasu」とだけ送ったときは、直前の返答で書いた本文か、作業フォルダの直下に指示のファイル以外の `.md` か `.txt` が1つだけあればそれを推敲します。ファイルを選んで推敲したときは、最終稿を同じフォルダにまだない名前で保存し、原文のファイルは書き換えません（作業フォルダに原稿を1つ置いて Codex で試した8本では、1.1.2 は8本とも「文章を貼ってください」と返し、2.0.0 は8本とも推敲しました）。

## 文書の種類と読者の指定

文書の種類と読者は、依頼の中で伝えられます。伝えなければ、スキルが行き先と本文の形から推定します。推定に自信がなく、答えによって直し方が変わり、問い返せる場面では、書き直す前に1回だけ確かめます。本文だけを返す指定、一回きりの実行、ほかのスキルの途中、「質問しないで」と頼まれたときは確かめず、種類を決めないまま、種類ごとの規則を当てずに直します。

```text
この障害報告を yomiyasu で、専門知識のない社外の利用者向けに読みやすくして。
（ここに修正したい文章を貼り付け）
```

種類ごとに、その種類で普通な書き方には当てない規則があります。値は付属ツールの `--doc-type` と同じです。

| 値 | 種類 | 当てない規則 |
|---|---|---|
| pr | PR説明 | 過剰な箇条書き（変更点、確認したこと） |
| article | 技術記事 | なし |
| incident | 障害報告 | 過剰な箇条書き（時系列）、硬い漢語（発生、復旧などの報告の語） |
| proposal | 提案書 | なし |
| minutes | 議事録 | 過剰な箇条書き（太字のラベルを含む）、同じ文末の連続（〜しました。の連続）、伝聞の「〜とのこと」 |
| manual | マニュアル | 過剰な箇条書き（番号つきの手順） |
| slides | スライド | 過剰な箇条書き（太字のラベルを含む）、数の宣言、繰り返すだけの「まとめ」、体言止めの項目での主語の抜けと文末、箇条の「〜のは、A、B、C」、他動詞を読点で並べる形 |
| essay | エッセイ・小説 | 読み取れる比喩（エッセイでも「効く」の類は直す）、小説のコピー調とダッシュ、見出しの比喩、他動詞を読点で並べる形 |
| formal | 公用文、規程、契約書、仕様書 | 硬い漢語（正式な語）、「〜を行う」「〜することができる」の外枠 |
| promo | 紹介記事・宣伝文 | 見出しのキャッチコピー、「！」と絵文字、勢いのある語と強める言葉、見出しの比喩、他動詞を読点で並べる形 |
| mail | メール・チャット | 宛名、挨拶、結び、署名、クッション言葉の削除、敬語の度合いと口語の書き換え、絵文字の削除 |
| paper | 論文・研究レポート | ぼかした語の具体化（慎重な言い方）、専門用語と論文調（本研究では）の言い換え、長い文の分割、名詞化の言い換え |
| script | 台詞・脚本 | 台詞の口調、言い回し、短い文を重ねる形（台詞の最後の「。」だけを外す。句点の指定があれば外さない）、見出しの比喩、他動詞を読点で並べる形 |

エッセイ・小説では、何を何に例えたかが読み取れる比喩を書き手の個性として残し、主語と述語が成り立たず連想もできない比喩を直します。紹介記事・宣伝文では、「！」（同じ段落に3つ以上あっても）、評価の語を短く重ねる型（安い。うまい。早い。）、同じ褒め言葉の繰り返しを残し、根拠のない誇張は書き換えずに書き手へ根拠を尋ねます。どちらも、書き手の表現を残したときは、そう判断したことを本文とは別に1行で伝えます。

メール・チャットで残すのは、宛名、挨拶、結び、署名、クッション言葉、敬語の度合い、チャットの口語で、直すのは敬語の誤りなどです。論文・研究レポートでは、慎重な言い方を断定に変えず、引用の書き方、数値、専門用語、「である」調を残します。

読者は3段階です。expert（同じ分野の専門家）には用語を残して説明を足しません。informed（分野は違うが技術に詳しい人）と general（専門知識のない人）では、その読者を指定されたときだけ、原文と資料にある説明で言い換えるか添えます。説明が原文と資料にないときは、説明を作らずに語を残し、「ここに説明が必要です」と書き手に返します。

種類を決めないときは、種類ごとの規則を当てません。分野別の指針（技術記事 tech、業務文書 business、エッセイ essay）は、種類を決めたあと書き方に迷うときに読みます（2.5.0 までは種類とは別に分野を決めて読む手順でした）。

## 書き手と読み手の指定

書き手の立場と、読み手との関係（上司、同じチーム、取引先、お客さまなど）は、依頼の中で伝えられます。

```text
draft.md を yomiyasu で読みやすくしてください。取引先の購買の担当者に送るメールです。
```

関係を伝えたときだけ、本文を次のように直します。

- 上司と社外の読み手には、読み手への依頼と読み手の行為を尊敬語に、社外の読み手に向かう書き手の行為を謙譲語に上げます。同じ動詞に「お・ご」を付けた形のほか、その関係で人がふつう書く言い回しも使います（来てください → お越しください、変更があれば言ってください → 変更があればお知らせください）。説明や手順を頼む「教えてください」は、「ご教示ください」か「教えていただけますか」にします。頼む中身、期限、選択肢、頼みの数は変えません。二重敬語と、原文にない「させていただく」は作りません。
- 読み手が社外の特定の相手なら、読み手に向けた言い回しとお詫びの文も、その関係で人がふつう書く形にします（申し訳ありません → 申し訳ございません、もっと → これまで以上に、気をつけます → 努めます）。作業を述べる文（直しました）は丁寧語のままです。
- 書き手が自分でした行為で、主語がなくほかの人の行為と読み違えうる文には、原文にある書き手の一人称（私、弊社など）を主語に補います（3か所まで）。原文に一人称がなければ補いません。
- 書き手の立場で知りえない事情、立場に合わない断定、関係に合わない言い方（お客さま宛ての「僕」など）は、本文を変えずに「書き手に確かめたい点」で知らせます（2点まで。ほかの確かめたい点の3点とは別に数えます）。
- 担当者、説明、挨拶、お詫びは足しません。エッセイと紹介記事・宣伝文では、書き手と読み手を伝えても本文を変えません。敬語を下げるのは、頼まれたときだけです。

伝えないときは、宛名や署名から読み手を推定しても、本文も知らせも変えず、推定した読み手を、変えなかった理由として返答に書くこともしません。確認の記録に、推定した値を1行だけ書きます。

## 構成と順序

読み手が最初に知りたいこと（用件、結論、依頼、期限、読み手がすること）が段落や文書の後ろにあれば、スキルはそれを前に出し、前置き、経緯、理由をその後に置きます。

- メール、お知らせ、報告、PR の説明、障害報告は、用件か結論から始めます。
- 段落の中でも、言いたいことを述べる文を先に置き、理由や例を後に続けます。
- 1段落に話題が2つ以上あれば段落を分け、同じ話題が離れた段落に散っていれば1か所にまとめます。
- 長くて掛かり方を追いにくい文は分けます。
- 3つ以上の並列の項目、手順、条件の組み合わせが地の文に詰まって読みにくければ、箇条書きか表にします。論理が繋がった説明を箇条書きで切っているときは、地の文に戻します。

以下の順序は、それ自体が内容なので並べ替えません。

- 時系列（経過、議事の流れ、体験、物語）
- 手順の順序と番号
- 条文、台詞、スライドのページのように、番号や位置で参照される単位
- 前の文を受けて後の文が成り立つ推論の積み上げ

依頼で構成や見出しの形を指定したときは、それに従います。順序や構成を変えた所は「変えたところ」に1行で書きます。

## 冗長さの削減

同じ文書で2回以上述べた内容と、除いても読み手が何も失わない文や語句を、スキルは削ります。削る前に、その箇所にしかない数値・条件・例外・理由がないかを確かめ、あれば残すか、残す側の文に移します。

- 冒頭の結論、本文、まとめ、箇条書きと直後の地の文が同じことを述べていれば、1か所に残します。
- 本文が述べていない極端な主張（必ず、完全に、すべて）を「〜わけではない」「〜とは限らない」で打ち消すのみの但し書きを削ります。
- 前に出た語の原語をもう一度書いた括弧、近い意味の語を中黒で並べた形（「確認・検証」）、一覧の項目ごとに書き直した同じ条件、中身のない副詞（実際に、しっかり）、直後の見出しを並べ直した「本記事の構成」を削ります。

本文にない条件や測った環境を述べる但し書き、読み手が知らないかもしれない語の初めの説明、保証を表す「必ず」は残します。型ごとの例と、Qiita の記事で数えた2019〜2021年と2026年の比較は `references/redundancy.md` にあります。

## 原文にない情報

スキルが根拠にするのは、原文、依頼、資料、この会話の利用者の発言、開いたファイル、コマンドの出力に書いてあることのみです。AI 自身やほかの AI の発言と一般の知識は使いません。原文から分からない動作主、原因、条件、数値、例、専門用語は推測で追加せず、ぼかした言葉をより狭い事実に置き換えません。要約の指定がなければ情報を省きません。同じ文書ですでに述べた内容の繰り返しと、原文が述べていない極端な主張を打ち消すのみの但し書きは、ここで言う情報に入りません。

書き換えても、主張、否定と比重、条件と範囲、言い切りの強さ、誰が誰に何をするか、数値・固有名詞・時期は変えません。これらを保てる言い方が見つからない所は、原文を残します。意味が変わっていないかを確かめる手順や検査はありません。

「昨日」のような相対の日付には、書いた日が確かに分かるときのみ、括弧で日付を添えます（昨日（3月4日））。エッセイ・小説と紹介記事・宣伝文、すでに日付があるとき、ほかの日付と矛盾するときは添えず、曜日も追加しません。添えたときは、何から数えたかを「変えたところ」に書きます。

## 完了報告

書き直した本文のあとには「変えたところ」（5点まで）、「残したAI特有の表現」、「書き手に確かめたい点」（3点まで。多いときは意味や誰が何をするかが変わる所から選び、残りの数を「ほかに N か所」と添えます）、「確認の記録」が付きます。「残したAI特有の表現」と「書き手に確かめたい点」は、書くことがあるときのみ付きます。

確認の記録は以下の3行です。

- 書き手・読み手・場面: 値ごとに、指定か推定かを添えます。決めなかった値は「決めていない」と書きます。
- 実行した検査: lint を実行したら「lint」と書きます。Python を実行できない環境では、スキルは目視で点検し、「lint（Python がないため実行しなかった）」と書きます。
- 見直し候補: 原文と最終稿に同じ引数で lint をかけ、「見直し候補: N件」の件数を「原文 N件 → 最終稿 M件」と書きます。「（件数は点数ではない。増減は読みやすさの良し悪しを示さない）」を添えます。新規作成では最終稿の件数のみです。

本文のみを返すよう頼んだときは、確認の記録も説明の欄も付けません。

## 資料から新しく書かせるとき

資料から新しく書かせると、スキルは依頼の読み手と目的に合わせ、資料にある事実で書きます。

2.0.2 からは名前を出さずに書かせると yomiyasu は使われません。「notes.md をもとに記事を書いて、最後に yomiyasu で推敲して」のように、書かせる依頼にも名前を入れてください。Claude Code 2.1.296 で、プラグインで入れた形とプロジェクトに置いた形のそれぞれに、notes.md のメモから社内ブログの記事を書いて最後に yomiyasu で推敲するよう3回ずつ頼むと、6回のすべてでスキルが読み込まれました。

## スキルの名前

2.0.2 から、エージェントが yomiyasu を使うのは、利用者が名前を出して頼んだときと、スキルでの推敲をはっきり頼んだときだけです。「/yomiyasu」と送るか、依頼の文に「yomiyasu で」と書けば呼べます。Codex では `$yomiyasu` のように、一覧に載っているスキルの名前を `$` に続けて書いても呼べます。名前を出さずに「読みやすくして」とだけ頼んだときと、名前を出さずに記事やコミットメッセージを書かせたときは使われません。

毎回使いたいときは、CLAUDE.md や AGENTS.md に1行を足します（[毎回 yomiyasu を使いたいとき](../README.md#毎回-yomiyasu-を使いたいとき)）。その1行に書くスキルの名前は入れ方で変わります。Claude Code では `npx skills add` と `gh skill install` で入れたときが `yomiyasu`、プラグインで入れたときが `yomiyasu:yomiyasu` です。Codex では `npx skills add` や `gh skill install` で入れたときも、`.agents/skills/` に置いたときも `yomiyasu` です（3.0.1 までは `yomiyasu:yomiyasu` でした）。Codex での名前の見分け方と、3.1.0 以降に更新したあとに書き換える所は、下の「Codex で使うリポジトリに置いたとき」にあります。`npx openskills install` で入れたときと、Claude.ai に ZIP で登録したときは `yomiyasu` を使います。

### Claude Code のプラグインで入れたとき

プラグインで入れたスキルは、Claude Code では `yomiyasu:yomiyasu`（プラグイン名とスキル名）という名前になります。スキルを名前で呼ぶときは、スラッシュの補完に出るとおり `yomiyasu:yomiyasu` と書いてください。外部の利用者の報告では、素の `yomiyasu` と書くと「Unknown skill」になり、スキルを読み込まないまま文章を書いていました。`npx skills add` などでスキルとして入れたときの名前は、素の `yomiyasu` です。

2.0.2 では Claude Code 2.1.296 で、プラグインで入れた形と、プロジェクトの `.claude/skills/yomiyasu/` に置いた形（`npx skills add` が置く場所）の両方を試しました。依頼は名前を出すかスキルでの推敲をはっきり頼む11種類で、「/yomiyasu」とだけ送るもの、`$yomiyasu:yomiyasu` に依頼の文を添えるもの、依頼の文に「yomiyasu で」「よみやすで」と書くもの、「日本語を推敲するスキルを使って」と頼むものなどです。それぞれを2つの形で3回ずつ送ると、合わせて66回のすべてでスキルが読み込まれました（[CHANGELOG](../CHANGELOG.md) の 2.0.2）。対話の画面では試していません。

### Codex で使うリポジトリに置いたとき

この置き方では、Codex がスキルを `yomiyasu` という名前で一覧に載せます。呼ぶときは「/yomiyasu」とだけ送るか、依頼の文に「yomiyasu で」と書いてください。一覧の名前どおり `$yomiyasu` と書いても呼べます。`npx skills add` や `gh skill install` で Codex に入れた場合も、名前と呼び方は同じです。

3.0.1 までに入れたフォルダをそのまま使っている場合は、名前は `yomiyasu:yomiyasu` のままです。その間は `$yomiyasu:yomiyasu` と書いてください。Codex がスキルの指示を自動で差し込むのは、`$` に続く名前が一覧の名前と1字ずつ同じときだけです。どちらの名前になっているかは、スキルのフォルダに `.codex-plugin/`（2.0.1 までの写しでは `.claude-plugin/`）があるかで分かります。`ls -a .agents/skills/yomiyasu` で見て、あれば `yomiyasu:yomiyasu`、なければ `yomiyasu` です。

3.0.1 まではスキルのフォルダにプラグインの設定（2.0.2 からは Codex 用の `.codex-plugin/plugin.json`、2.0.1 までは `.claude-plugin/`）を入れていたので、名前が `yomiyasu:yomiyasu` でした。3.1.0 でこの設定を外しました（理由は [CHANGELOG](../CHANGELOG.md) の 3.1.0）。3.1.0 以降に更新するか入れ直して、スキルのフォルダからこの設定がなくなると、名前が `yomiyasu` に変わります。変わったあとは、次の3つを書き換えてください。

- 依頼の文の `$yomiyasu:yomiyasu` を `$yomiyasu` にします。スクリプトや CI に書いた依頼の文も同じです。
- `AGENTS.md` に足した1行の `yomiyasu:yomiyasu` を `yomiyasu` にします（[毎回 yomiyasu を使いたいとき](../README.md#毎回-yomiyasu-を使いたいとき)）。
- Codex の設定でスキルを名前で指定している場合は、その名前を `yomiyasu` にします（`config.toml` の `[[skills.config]]` の `name`、`environments.toml` の `skills` の `required`）。

書き換える前の書き方のままでも、測った範囲ではスキルは読まれました。名前が `yomiyasu` の形のときに、`$yomiyasu:yomiyasu` と書いた依頼を3回、「yomiyasu:yomiyasu で」と書いた依頼を2回、`AGENTS.md` の1行を `yomiyasu:yomiyasu` のままにして名前を出さない依頼を3回送ると、8回ともモデルが自分で SKILL.md を読みました（codex-cli 0.164.0、gpt-6-astra、effort high、`codex exec`）。この8回に、Codex がスキルの指示を自動で差し込んだ回はありません。読むかどうかはモデルしだいなので、依頼の文と `AGENTS.md` の1行は書き換えてください。3つ目の設定の名前は、この8回では試していません。こちらも書き換えてください。逆に、名前が `yomiyasu:yomiyasu` のままの形のときに、`$yomiyasu` と書いた依頼と、`AGENTS.md` の1行を先に `yomiyasu` に書き換えて名前を出さない依頼を2回ずつ送っても、4回ともスキルを読みました。この4回にも、Codex がスキルの指示を自動で差し込んだ回はなく、モデルが自分で SKILL.md を読んでいます。

Codex はスキルのフォルダから上のフォルダへ順にプラグインの設定（`.codex-plugin`、`.claude-plugin`、`.cursor-plugin` の `plugin.json`）を探し、最初に見つけた設定の名前をスキルの名前の先頭に付けます。そのため、次の形では名前が `yomiyasu` になりません（codex-cli 0.164.0 で、一覧の名前を確かめました）。

- このリポジトリを clone して、`.agents/skills/yomiyasu` を clone の中の `skills/yomiyasu` への symlink にした形と、このリポジトリを Codex のプラグインとして入れた形（`codex plugin marketplace add nanaism/yomiyasu` と `codex plugin add yomiyasu@yomiyasu`）では、3.1.0 以降も名前は `yomiyasu:yomiyasu` です。このリポジトリの直下にある `.claude-plugin/plugin.json` の名前が先頭に付きます。
- スキルを置いたリポジトリか、その上のフォルダに別のプラグインの設定があると、その設定の名前が先頭に付きます（Claude Code のプラグインを開発しているリポジトリに置いたときなど）。`$` で呼ぶときは、一覧に載っている名前をそのまま書いてください。

更新したあともスキルのフォルダにプラグインの設定（`.codex-plugin/`。2.0.1 までの写しでは `.claude-plugin/`）が残っているときは、名前は `yomiyasu:yomiyasu` のままです。この設定は `gh skill install --force` のように、前のフォルダを消さずに新しいファイルを重ねる入れ方で残ります。残った設定のフォルダを消してください。スキルのフォルダを消してから入れ直してもかまいません。README の「6. Codex で使うリポジトリに置く」のコマンドは、前のフォルダを別の場所へ移してから入れるので、残りません。

写しは1か所だけに置いてください。利用者のスキルの置き場所（`~/.agents/skills/`）とリポジトリの `.agents/skills/` の両方に置くと、一覧に2つ載ります（codex-cli 0.164.0 で、一覧だけを確かめました）。

2.0.0 で確かめたのは、macOS の codex-cli 0.162.1 で、作業場所の `.agents/skills/yomiyasu/` に置いたスキルを読んで推敲したことだけです（[確かめた範囲](./limitations.md#確かめた範囲)）。Codex Cloud、利用者のスキルの置き場所（`~/.agents/skills/`）に置く形、Windows では確かめていません。写したフォルダは自動では新しくならないので、更新するときは同じ手順で写し直してください。
