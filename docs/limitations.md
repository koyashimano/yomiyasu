# 限界と確かめた範囲

README の[限界](../README.md#限界)の節を詳しく書いたものです。

付属の lint は、決まった形を拾うものです。意味が保たれたかと読みやすいかは、元の文と読み比べて人が確かめてください。

下の「3.0.0 の SKILL.md で測ったこと」と「確かめた範囲」の数は、3.1.0 までの SKILL.md で測ったものです。そこに出てくる diff、check、フックは当時同梱していた検査で、現在の本体にはありません。現在の SKILL.md は構成と順序を組み替える決まりを追加し、意味が変わる恐れの検査を削除したので、これらの結果が現在の SKILL.md でもそのまま成り立つとは言えません。

## 書き手と読み手

敬語を上げる形は、同じ動詞に「お・ご」を付けた形と、人がふつう書く言い回しのどちらかを選びます。どちらが自然かは文脈で変わり、2つのモデルがそろって自然とはしなかった言い換えも残ります（測った原稿の取引先への依頼で、Claude Code の2回の20か所のうち3か所）。書き手の主語を補う文は、原文に書き手の一人称がある文書だけで、チームや会社の決定とも読める文には補いません。依頼で関係を伝えなかったときは、宛名から社外あてと分かっても敬語を上げません。

## 2.1.1 で直した lint の限界

lint の文末の飾り、比喩の「効く」、translated_term、slop_vocabulary、「〜した瞬間」の判定には、以下の限界があります。

<details>
<summary>細かい形</summary>

- lint の文末の飾りを読み飛ばすのは、文末を見る規則だけです。文頭の飾り（「🚀 結論から言うと」）は読み飛ばさないので、文頭に固定した規則は、先頭に飾りがあると当たりません。句点の代わりの絵文字で文を分けて見るのも、文末の型を見る規則（meta_filler の文末の型、negative_parallelism の「Aじゃない、Bです」、instruction_residue、sentence_end_repetition）だけです。絵文字のあとが助詞、長音、かっこ、記号のときと、絵文字の前が助詞か読点のときは、文が続いているとみて分けません。閉じかぎと閉じ引用符を読み飛ばすのは、同じ段落のその行までに対の開きがない行だけで、閉じかっこを読み飛ばすのは、対の開きかっこが文頭、句点、述語のすぐあとにあるときだけです。文末のコロン（trailing_colon）は、後ろの絵文字を読み飛ばしません（「状態：✅」の絵文字は値のことがあるためです）。
- lint の比喩の「効く」は、主語のない「効いてきた」を、同じ文、同じ行の前の文、前の3行に文字どおりの語（服用、エアコン、ブレーキ など）があるときだけ文字どおりとみなします。それより前に語があるときは拾い、前の3行にその語があると比喩でも拾いません。手順を表す語（見直し、工夫、改善 など）を主語にしない「効く」（その一言が効いた、この差が効く）と、打ち消し（効かない、効いていない）は拾いません。ただし 2.1.0 から拾っている「地味に効かない」のような副詞の形は今までどおり拾います。
- lint の translated_term は文を1行ずつ見るので、「この辞書の」と「次の版では」が別の行に折り返されているときや、前の文に出版物の語があるときは、出版物の版でも警告します。
- lint の slop_vocabulary の「装置」は、機器の名前を作る語の一覧（安全、制御、記憶、表示、測定 など）との複合語と、カタカナや英数字の語のあとの「装置」だけを除きます。一覧にない機器の名前（電子顕微鏡装置など）には文字どおりでも警告し、一覧にある語との複合語を比喩で使ったとき（町は記憶装置だ）は警告しません。
- lint の metaphor_verb の「〜した瞬間」は、決まった形と抽象的な主語の語の一覧で、時刻の表現と直訳の形を分けています。一覧にない抽象語が主語の一般論（〜した瞬間に、チームは考えるのをやめる）には警告せず、具体的な主語と大げさな結果が並ぶ文（マージした瞬間にテストが全滅した）には警告します。「〜のは、〜した瞬間だった」のように時刻を答える文は、大げさな言い方（すべてが変わったのは、〜した瞬間だった）でも警告しません。
</details>

## lint の直訳語の段と門

3.3.0 で lint の直訳語の型4に追加した「段」と「門」は、人が書いた文でも文字どおりの意味で使われるため、字の形と同じ文にある言葉で検出の条件を絞っています。そのため、AI が書いた文書で stage の意味で使った段でも、以下の形には指摘が出ません。

- 同じ文に処理の流れを表す言葉がない「公開の段」のような形と、「推敲の段の指摘」のように「の段」のあとに「の」が続く形
- 「この段」「その段」（改まった文の「その段はご容赦ください」と区別できないためです）
- 「第二段」のような漢数字の段と、「第2段目」
- 「段a」のような小文字の英字の名前

一方、同じ文に処理の流れか検査を表す言葉があると、文字どおりの意味の段や門（「棚の段に学習の本を並べた」「学校の門の前でテストの結果を待った」）にも指摘が出ることがあります。どちらも info の指摘で、`--strict` と `--fail-on` の判定と `rule_penalty_score` には入りません。
